# Task 12: Post-Race Detailed Analytics Implementation Plan

## Overview
Create a comprehensive post-race analytics system with visual charts, detailed metrics, and "What If" scenarios. This will be displayed as a collapsible "Deep Dive" section on the result screen.

## Components to Create

### 1. Analytics Service (`src/services/analytics/race-analytics.ts`)
**Purpose**: Process SimulationResult data and compute analytics

**Key Functions**:
- `analyzeRacePerformance(result, challenge, preparation)` - Main analyzer
- `calculatePaceMetrics(stateLog)` - Compute pace stats (avg, best, worst, variability)
- `calculateEnergyMetrics(stateLog)` - Energy drain rate, consumable usage
- `calculatePositionProgression(stateLog)` - Position at each km
- `identifyCriticalMoments(result)` - Extract key events with impact
- `generateWhatIfScenarios(analytics, result)` - Generate 2-3 scenarios
- `saveAnalytics(challengeId, analytics)` - Store in localStorage (last 10)
- `loadAnalytics(challengeId)` - Retrieve stored analytics

**Data Structure**:
```typescript
interface RaceAnalytics {
  raceId: string;
  date: string;
  splits: { km: number; pace: number; time: number }[];
  bestSplit: { km: number; pace: number };
  worstSplit: { km: number; pace: number };
  averagePace: number;
  paceVariability: number;
  energyDrainRate: number;
  energyCurve: { km: number; energy: number }[];
  momentumPeaks: number[];
  fatigueProgression: { 
    km: number; 
    muscle: number; 
    mental: number;
  }[];
  positionProgression: { km: number; position: number }[];
  consumableUsage: { km: number; item: string; energyBefore: number }[];
  criticalMoments: { 
    km: number; 
    event: string; 
    impact: string;
    statsChange: { energy?: number; focus?: number }; 
  }[];
  whatIfScenarios: WhatIfScenario[];
}

interface WhatIfScenario {
  id: string;
  title: string;
  description: string;
  estimatedImpact: string; // e.g., "23 seconds faster"
  confidence: "high" | "medium" | "low";
}
```

### 2. Analytics Component (`src/components/race/post-race-analytics.tsx`)
**Purpose**: Visual analytics dashboard with 5 sections + What If

**UI Structure**:
- Collapsible panel (starts collapsed)
- Tab-based navigation OR vertical scrollable sections
- Each section is self-contained with header + visualization

**5 Main Sections**:

1. **Pace Chart** 
   - SVG line chart showing pace per km
   - Highlight best split (green) and worst split (red)
   - Average pace baseline (dashed line)
   - Use existing CSS/SVG approach (no external chart library)

2. **Energy Curve**
   - SVG area chart showing energy decline
   - Markers for consumable usage (💧 water, ⚡ gel, etc.)
   - Color gradient: green → yellow → red zones

3. **Position Progression**
   - Step chart showing position at each km
   - Highlight overtakes (↑) and being overtaken (↓)
   - Simple bar representation with position numbers

4. **Fatigue Split**
   - Stacked bar chart: muscle fatigue (blue) + mental fatigue (purple)
   - Show per km progression
   - Highlight critical fatigue points (> 80%)

5. **Critical Moments Timeline**
   - Vertical timeline with km markers
   - Event cards showing:
     - Event name/description
     - Impact assessment (+/- stats)
     - Icon based on event type
   - Color-coded by impact severity

**What If Simulator Section**:
- Below the 5 charts
- Show 2-3 generated scenarios
- Each scenario as a card with:
  - Emoji icon
  - Title
  - Description
  - Estimated impact (bold, highlighted)
  - Confidence badge

**Styling**:
- Match existing result screen style: `rounded-[2rem]` cards
- Dark mode support
- Framer Motion animations for panel reveal
- Responsive: stack charts on mobile

- Load on result screen mount for comparison features

### 4. Data Processing Logic

**Pace Calculation**:
- Extract from stateLog: `(state.accumulatedTime - prevState.accumulatedTime)` per km
- Standard deviation for variability
- Identify best/worst by comparing all splits

**Energy Analysis**:
- Track energy per km from stateLog
- Calculate drain rate: `(startEnergy - endEnergy) / totalKm`
- Match consumable usage with energy before/after

**Position Tracking**:
- From stateLog, get opponents array per km
- Sort by distance/time to compute player position
- Track changes for overtake detection

**Critical Moments**:
- Use existing `result.events` array
- Match with stateLog to get before/after stats
- Compute impact: positive/negative/neutral

**What If Scenarios**:
Three scenario types:
1. **Steady Pace**: "If you maintained your best split pace throughout..."
2. **Better Timing**: "If you used nutrition at km X instead of km Y..."
3. **Energy Management**: "If you started more conservatively..."

Calculate estimated time difference using simple projection.

## Design Decisions

**Why no external chart library?**
- Keep bundle size small
- Match existing SVG-based visualizations (splits table pace bar)
- More control over styling and dark mode

**Why collapsible?**
- Result screen is already long
- Not all players want deep analytics
- Progressive disclosure pattern

**Why last 10 races?**
- Balance between history and storage
- Enough for trend analysis
- Prevents localStorage bloat

**Why local storage?**
- No backend integration needed
- Fast access
- Per-device history (acceptable for now)
